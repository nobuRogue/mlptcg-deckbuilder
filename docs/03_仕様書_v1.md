# 仕様書 v1：MLPTCG デッキビルドツール

- 作成: 2026-10-01
- 出典: コアルール PDF（第一節 2.0.0〜2.2.0、第二節 4.4.0 / 6.1.0）、公式 Q&A

## 1. デッキ構築ルール（検証対象）

ゲームデッキは以下 4 つで構成する。

| 区分 | 枚数 | 入れられるカード種別 |
|---|---|---|
| メインデッキ | ちょうど 50 枚 | キャラ / イベント / アイテム |
| シーンデッキ | ちょうど 15 枚 | シーン |
| ストーリーデッキ | ちょうど 4 枚 | ストーリー |
| 主役 | ちょうど 1 枚 | 主役 |

### 1.1 同一カードナンバー制限（R-COPY）
- ゲームデッキ全体で、同じカードナンバーのカードは最大 4 枚。
- 先頭の `※`（キラキラマーク）を除いた番号が同じなら同一カード扱い。
  - 例: `SD01-ER07` と `※SD01-ER07` は合算。
  - 公式データ上で同じ番号の別レコード（別イラスト・再録）も合算。
- 例外: 「日常シーン」は枚数無制限。
  - 判定: 公式データの `keyword` に「日常」を含むシーン（例: BP03-ER01 ナイトメアナイト広場）。
    `overrides.json` の `dailySceneCardNos` でも補える。

### 1.2 ストーリーデッキ（R-STORY）
- 4 枚すべてメインタイトルが同一。
- 段階（ステージマーク 1〜4）がそれぞれ 1 枚ずつ。
- データ上の扱い:
  - メインタイトル = `name` の `——` より前
  - 段階 = `keyword` の「ステージマーク N」

### 1.2.1 トークン（R-TOKEN）
- 種別「トークン」（カード番号 `TK-`）はデッキに入らない（コアルール 第二節 7.1.0）。
- カード一覧には「デッキ外」タグ付きで表示するが、追加はできない。共有コードに含まれていれば無効とする。

### 1.3 主役（R-LEAD）
- 主役カード 1 枚。（両者合意があれば代用可能だが、ツールでは警告扱いにする）

## 2. データ

- 取得元: 公式 cardlist ページの `__NEXT_DATA__.props.pageProps.site.cards`
- 取得スクリプト `app/scripts/fetch-cards.mjs` で `app/src/data/cards.json` を生成。
- 主キー: `recordId`（公式の `id` は重複するため）。
- 正規化:
  - `harmony` / `idea` を数値化（空は null）
  - `cardNo` = `id` から先頭 `※` を除いたもの（枚数制限の単位）
  - `keyword` を `/` で分割した配列
  - `effect` の改行コードを LF に統一
  - ストーリー: `storyTitle`, `storyStage` を付与
- 補正ファイル `app/src/data/overrides.json`: 公式データに無い情報を手で補う（現在は空）。
- 効果文の書式: 能力アイコンは `*出会い*` / `＊ひらめき＊` のように記号で囲まれ、
  起動コストは `*冒険エリア#横置き*` のように `#` 以降に書かれる（ナイトメアナイト以降）。
  詳細画面ではアイコンをタグ、コストを枠付き文字で表示する。

## 3. 画面（v1）

- 左: カード一覧（画像グリッド）＋検索・絞り込み
  - フリーワード（名前・キーワード・効果文・カード番号）
  - 種別 / 収録弾 / レアリティ / ハーモニー / アイデア
- 右: 編集中のデッキ
  - 区分ごと（主役・ストーリー・メイン・シーン）の枚数表示と一覧
  - ルール違反の一覧表示（違反があっても保存は可能）
- クリックで追加、デッキ側のクリックで削除。カード詳細はモーダル表示。
- カード拡大表示（2026-10-02 追加）
  - カード一覧の各カード右上に拡大ボタン（虫眼鏡＋）。押すとカード画像を画面いっぱいに表示。
  - 拡大ボタンではデッキに追加されない（カード本体のクリックは従来どおり追加）。
  - 背景クリック・Esc・右上の×で閉じる。
- ハーモニー分布（2026-10-02 追加）
  - 対象はメインデッキ。横軸ハーモニー（1〜7 は常に表示、8 以上は該当時のみ）、縦軸枚数。
  - 種別（キャラ／イベント／アイテム）で積み上げ。各棒の上に合計枚数、凡例に種別ごとの合計。
  - 見出しに平均ハーモニー。棒にカーソル（スマホはタップ）で種別内訳を表示。

## 4. 保存・共有

- 複数デッキをブラウザ（localStorage）に保存。名前を付けて切替。
- 共有 URL: `#d=<デッキコード>`。デッキコードは `カードナンバー×枚数` を圧縮したもの。
  - 別イラスト違いを区別するため、内部的には recordId を使う。
- テキスト書き出し（大会提出用リストを想定）。
- デッキビュー（2026-10-03 追加）: 画像共有用の一覧画面。デッキ欄の「デッキビュー」ボタンで開く。
  - 主役・ストーリー・キャラ・イベント・アイテム・シーンの種別ごとに、全カード画像と枚数（×N）を表示。
  - 見出しにデッキ名、区分ごとの枚数、構築ルールの適否。フッターにツール名と最終更新日。
  - 種別のまとまりは横に詰めて並べ、PC（1280×900 程度）で1画面に収まるようにする。スマホは5列。
  - 画像の書き出しはスクリーンショットで行う。公式画像サーバーが CORS を許可していないため、
    ブラウザ内での PNG 生成はできない（キャンバスが汚染され書き出し不可）。

## 5. 公開

- 静的サイトとしてビルドし、ホスティングサービスに配置（公開先は別途決定）。
- カード画像は公式 URL を直接表示し、複製しない。
